JVM Memory Visualizer

Step through simulated Java stack, heap, string pool and garbage collection.

Supported statement shapes
  • Type name = new Class(args); — declaration + object creation
  • Type name = other; — declaration + reference/primitive copy
  • Type name = "literal" | 123 | true; — declaration + literal
  • Type name = null; — declaration + null init
  • Type name; — bare declaration
  • static Type name = ...; — static field
  • name = new Class(args); — reassignment to a new object
  • name = other; / name = "lit"; / name = null; — assignment
  • owner.field = value; — field assignment (value, null, var ref, or new Class(args))
  • name(); / owner.method(); — bare method call
  • name = owner.method(); / Type name = owner.method(); — call with captured result

This simulates a fixed set of statement shapes, not a full Java interpreter — method bodies are never executed, so a captured call result is always modeled as unknown, and calls like System.out.println(...) aren't supported since they don't touch stack/heap memory.
